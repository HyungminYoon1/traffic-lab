# TRAFFIC LAB architecture

## Purpose

Single-lane 1 km ring-road traffic with bounded IDM-inspired following, one-car braking, editable density/speed/time gap and measured model metrics. Seeded traffic-control challenges add timed driver-policy interventions and a temporary speed-restriction segment on the same lane; free experiment remains available.

## Structure

Independent static GitHub Pages site at /traffic-lab/. dist/src/model.js owns pure calculation; dist/src/app.js owns UI, bounded inputs, playback and page lifecycle; dist/styles.css owns responsive presentation. SI-unit ring-road model -> geometry/chart renderer; fixed substeps and collision bounds independent of UI.

dist/src/challenge.js is a pure model-layer module for deterministic event schedules, intervention budgets, paired baseline simulation, bounded measurement windows and target evaluation. Every production step is 0.05 seconds; the challenge clock uses integer ticks. The UI never decides a score. The original IDM-inspired acceleration, actual units, vehicle length, ring geometry and non-overlap boundary are preserved. A restriction segment changes desired speed, not topology or the car population. No intersections, lane changes, entry/exit or extra traffic streams.

Challenge state consists of two worlds of at most 60 cars, at most 1200 substep samples (final 60 seconds), at most 240 chart samples per world, a fixed schedule of at most three events and an intervention log of at most six entries. Each UI frame performs at most 20 paired steps; deliberate 10-second advance performs at most 200. Challenge runs stop after 180 or 240 model seconds. Live worlds and free-experiment history disappear with the page; explicit policies and independently completed challenge policies may persist locally as described below.

No backend, account, tracking, cookies, external fonts, runtime API or public ranking. Optional page-scoped WebMCP tools use the same validated state/actions as the visible controls, and feature-detect unsupported browsers. They cannot inject results, bypass replay lock or access saved policies.

## Policy, measurement and storage boundaries

The existing three-mission campaign remains `idm-v1`: unchanged IDM physics, mission seeds, events, budgets, checkpoints, targets and 30/60-second intervention duration/cost. Original late-start interventions remain legal: full cost is charged and the challenge still stops at mission end even if the requested duration extends past it. `dist/src/policy.js` owns pure schema validation and deterministic replay. The JSON policy is `{version:1,campaign:"idm-v1",mission,seed,actions:[{tick,speed,timeGap,duration}]}`. It has exact keys, integer ticks, seed 1–9999, known missions, existing numeric parameter ranges, at most six sorted non-overlapping actions, and mission-specific budget bounds; action starts must precede mission end. Import is limited to 4096 UTF-8 bytes before parsing; no names, HTML, terminal worlds, scores, achievement claims or arbitrary metadata. The UI checks file size before reading. Replay creates both worlds from the recorded mission/seed and applies validated inputs at exact ticks. It never trusts a terminal state (`validatedReplaynottrustedterminalstate`). Replay is visible, paused initially, runs through existing bounded frame/advance controls, and locks additional interventions. Reset returns to independent play.

`challenge.js` retains all scoring and adds same-window observations without changing the existing result. Per-step detector crossings integrate actual wraparound at the fixed start line; detector throughput is crossings / seconds × 3600, distinct from whole-ring distance-derived flow. Stopped vehicle-seconds sum vehicle counts below 0.1 m/s × DT at each step's end. Time loss in vehicle-seconds sums max(0, 1 − observed speed / original mission desired speed) × DT per vehicle at step ends, using the same fixed reference for both worlds even during an intervention/restriction. Recent windows are at most 60 seconds; checkpoint observations cover 20 seconds. UI deltas describe these model observations without asserting real-world causal effects.

`dist/src/storage.js` alone owns private policy persistence at `traffic-lab-policies-v1`: strict `{version:1,entries:[{policy,independent:boolean}]}`, up to 10 unique policies, at most 49152 UTF-8 bytes. No separate run histories, identity, timestamps or settings stores. Explicit save/import adds a policy without completion credit; manual success automatically saves the actual policy as independent after full deterministic re-execution verifies all goals and checkpoint. Failed runs, imports and replay do not create independent achievements. The count is unique missions with durable independently completed policies that still pass full replay, maximum three. Results/flags in imported files are rejected. A flag in private local storage alone cannot pass without a valid successful replay. Browser storage is user-controlled and provides local provenance, not tamper-proof or server attestation. Storage full/blocked errors cannot create a durable achievement. Deduplicate exact policies; no automatic eviction. Selected delete and full clear are explicit. Deleting the last retained independent success of a mission reduces the count. If saving a successful run fails, delete a saved entry then save the still-current completed run.

`dist/src/progress.js` is the minimal aggregate storage boundary at `web-lab-progress-v1`: `{version:1,apps:{[repoId]:{completed:integer,total:integer,updatedAt:ISO string}}}`. A fixed whitelist of the 15 existing service directory IDs bounds the object; completed 0..total<=1000, exact record keys, canonical ISO timestamps and maximum 8192 characters. Read-modify-write preserves other allowlisted app records. Only traffic-lab's durable, replay-verified independent achievements publish a count with total 3 and the actual write time. Viewing the page, hints and imports do not grant completion. At zero achievements remove only traffic-lab's summary; full clear removes only traffic-lab's private key and summary. Malformed existing aggregates fail safely without overwriting other apps. Summary failures are reported separately from private policy saves. The gallery can read counts; it never needs seeds, actions or private policy payloads. No changes to gallery/other repositories are part of this implementation.

No eval, user HTML injection or remote embeds. External links use noopener/noreferrer. CSP restricts connections and execution; GitHub hosting logs are separate. Only dist is deployed. UTF-8 without BOM / CRLF. Preserve all other repositories.
