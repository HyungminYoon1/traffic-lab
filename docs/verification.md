#### 메인 브라우저 QA 인계

`npm run dev -- 0`의 로컬 주소에서 확인합니다. 새 도전은 정지 상태로 시작합니다. 실제 렌더링·클릭·키보드·반응형·콘솔 및 WebMCP 등록 여부는 이 체크리스트를 실행한 후 별도 증거로 추가해야 합니다.

1. 첫 화면에서 도전 설명/예산/목표 확인. 도로 클릭·방향키가 선택만 하며 도전 중 임의 급제동·차량 수 변경을 할 수 없는지 확인. 자유 실험으로 전환하면 기존 슬라이더/프리셋/제동이 동작하는지 확인.
2. **wave 시드 4 성공 경로:** 0초에 60 km/h·2.2초·60초 개입 → 10초 진행 12회(120초) → 60 km/h·0.7초·60초 개입 → 10초 진행 6회. 90초 중간 통과 및 종료 성공·비교표·기록 확인. 유지 중 적용 버튼 비활성, 60초 만료 복귀, 남은 예산 0 확인.
3. **bottleneck 성공 경로:** 시드 4로 준비 → 100초까지 진행(20초 제한 표시, 100초 다음 계산에서 해제) → 60 km/h·0.7초·60초 → 180초까지 진행 → 동일 60초 개입 → 240초까지 진행. 중간 160초 통과와 종료 성공 확인.
4. **echo 성공 경로:** 시드 4로 준비 → 90초까지 진행 → 60 km/h·1.0초·30초 → 180초까지 진행 → 60 km/h·0.7초·60초 → 240초까지 진행. 중간 120초 통과와 종료 성공 확인.
5. 실패/재현: 무개입으로 끝까지 진행하면 실패. bottleneck은 180초에만 대표 정책을 적용하면 최종 목표가 충족되어도 중간 검사 미달로 실패. 처음부터 재시도가 같은 시드·도로 조건과 예산으로 복귀하는지 확인. 잘못된 시드 0/10000/소수는 현재 도로를 바꾸지 않고 거절해야 합니다.
6. 320/390 px 및 데스크톱에서 넘침/표/선택/키보드 포커스 확인. 재생·일시 정지·10초 진행·배속 1/4/8·탭 숨김과 reduced-motion 확인. 종료 후 시간은 멈추며 자동으로 다음 도전으로 넘어가지 않아야 합니다. 그래프·비교표 수치는 모델 상태에 따라 변해야 합니다.
7. WebMCP 지원 브라우저에서 read_traffic_state, prepare_traffic_challenge, intervene_traffic 호출과 도전 중 configure_traffic/brake_traffic_car 거절 확인. 지원하지 않는 환경에서도 일반 UI가 정상 실행되어야 합니다. 함수 검증은 Node 증거와 브라우저 호출 증거를 구분합니다.
